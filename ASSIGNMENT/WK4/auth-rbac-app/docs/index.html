Security checklist

The AI-generated code was reviewed against four checks before it was trusted.

Password storage

Salted scrypt (N=217, r=8, p=1), the OWASP-recommended setting. No plaintext, no MD5 or SHA-256.

Server-side enforcement

A requireRole('admin') guard runs on every admin request. The role comes from the database, never from the client.

Secrets & safe output

Secrets live in .env. Password hashes are never returned in any API response.

No user enumeration

Wrong password and unknown user return the same message: “Invalid username or password.”

An issue caught during generation

The AI's own test run caught a problem in its first version and corrected it before handing over the code.

A rate limiter that would lock out a whole office

The first login rate limiter counted failures by IP address and by username together, both capped at 5. Everyone behind one shared network (a school, an office) would be locked out after a few typos by anyone.

Fix: two separate limits, 5 failed attempts per account to stop password guessing and 50 per IP to stop credential spraying.
